# 宝塔面板原生部署指南

本文档介绍如何在宝塔面板中原生部署 `fettle-standalone`，不依赖 Docker 容器。适用于需要使用宝塔进程管理、网站管理与环境变量管理的场景。

## 1. 前提条件

- 已安装宝塔面板
- 宝塔面板支持"软件商店""文件""终端""计划任务"
- 建议宝塔已安装以下软件模块：
  - PostgreSQL
  - Redis
  - MongoDB
  - Node.js
  - Python
  - Go
  - Nginx

## 2. 目录与代码准备

### 2.1 上传代码

将项目完整代码上传到服务器路径，例如：

```text
/www/wwwroot/fettle-standalone
```

### 2.2 推荐目录结构

```text
/www/wwwroot/fettle-standalone/
  .env.example
  .env
  backend/
  frontend/
  proto/
  deploy/
  docs/
  scripts/
  build/          ← 编译产物输出目录
```

### 2.3 复制环境变量模板

在项目根目录执行：

```bash
cd /www/wwwroot/fettle-standalone
cp .env.example .env
```

### 2.4 编辑 `.env`

必须修改以下关键变量：

- `JWT_SECRET`
- `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME`
- `REDIS_ADDR`
- `MONGO_URI`
- `MINIO_ENDPOINT` / `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY`
- `NATS_URL`
- `MILVUS_HOST` / `MILVUS_PORT`
- `QWEN_API_KEY` / `DEEPSEEK_API_KEY`

> 建议使用统一 `.env` 文件，不要在宝塔面板里手动复制多份敏感值。

## 3. 依赖服务准备

### 3.1 PostgreSQL / Redis / MongoDB

优先使用宝塔软件商店安装，并确认服务已启动。

- PostgreSQL：创建数据库 `standalone`；创建用户并设置密码
- Redis：默认监听 `6379`
- MongoDB：默认监听 `27017`（可通过 Docker 安装：`docker run -d --name fettle-mongodb -p 27017:27017 --restart always mongo:7`）

### 3.2 MinIO / NATS / Milvus

宝塔通常不直接提供这些服务，需要在终端中原生安装或使用脚本部署。

推荐使用已添加的脚本：

```bash
bash /www/wwwroot/fettle-standalone/scripts/install_minio_nats_milvus.sh
```

如果脚本不适用，也可手动参考：
- MinIO: https://min.io/docs
- NATS: https://nats.io/download
- Milvus: https://milvus.io/docs （推荐 Docker Compose 部署，参考 `deploy/milvus/docker-compose.yml`）

## 4. 编译后端 Go 服务

建议先在终端中编译所有 Go 后端服务，并将可执行文件输出到统一目录。

```bash
cd /www/wwwroot/fettle-standalone
mkdir -p build

cd backend/gateway && go build -o ../../build/gateway . && cd ../..
cd backend/user-service && go build -o ../../build/user-service . && cd ../..
cd backend/agent-service && go build -o ../../build/agent-service . && cd ../..
cd backend/chat-service && go build -o ../../build/chat-service . && cd ../..
cd backend/skill-service && go build -o ../../build/skill-service . && cd ../..
cd backend/billing-service && go build -o ../../build/billing-service . && cd ../..
```

> 如果 `go build` 失败，请先确认 `go version` 正常，`GOPATH` 等环境变量正确。

## 5. 安装 AI 引擎 Python 依赖

```bash
cd /www/wwwroot/fettle-standalone/backend/ai-engine
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

如果宝塔面板有 Python 环境管理，确保使用该环境或指定虚拟环境路径。

## 6. 前端构建

以 `web-admin` 为例：

```bash
cd /www/wwwroot/fettle-standalone/frontend/web-admin
npm install
npm run build
```

构建完成后，静态目录为：

```text
/www/wwwroot/fettle-standalone/frontend/web-admin/dist
```

## 7. 服务管理（二选一）

> **重要：宝塔 Go 项目管理器和 systemd 只能选一种来管理同一组服务，不能同时使用，否则端口冲突。**

---

### 方案 A：使用 systemd 管理（推荐）

适合习惯命令行操作、需要精细控制启动顺序和依赖关系的场景。

#### 7A.1 创建 systemd 服务文件

为每个 Go 服务创建 service 文件：

```bash
for svc in gateway user-service agent-service chat-service skill-service billing-service; do
cat > /etc/systemd/system/fettle-standalone-${svc}.service << EOF
[Unit]
Description=Fettle Standalone ${svc}
After=network.target

[Service]
WorkingDirectory=/www/wwwroot/fettle-standalone
ExecStart=/www/wwwroot/fettle-standalone/build/${svc}
Restart=always
RestartSec=5
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
EOF
done
```

AI 引擎 HTTP 服务：

```bash
cat > /etc/systemd/system/fettle-standalone-ai-engine.service << 'EOF'
[Unit]
Description=Fettle Standalone AI Engine HTTP
After=network.target

[Service]
WorkingDirectory=/www/wwwroot/fettle-standalone/backend/ai-engine
ExecStart=/www/wwwroot/fettle-standalone/backend/ai-engine/venv/bin/uvicorn main:app --host 0.0.0.0 --port 20007
Restart=always
RestartSec=5
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
EOF
```

AI 引擎 gRPC 服务（agent-service 依赖此服务，必须先启动）：

```bash
cat > /etc/systemd/system/fettle-standalone-ai-grpc.service << 'EOF'
[Unit]
Description=Fettle Standalone AI Engine gRPC
After=network.target

[Service]
WorkingDirectory=/www/wwwroot/fettle-standalone/backend/ai-engine
ExecStart=/www/wwwroot/fettle-standalone/backend/ai-engine/venv/bin/python run_grpc.py
Restart=always
RestartSec=5
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
EOF
```

#### 7A.2 启动服务

```bash
systemctl daemon-reload

# 注意启动顺序：ai-grpc 必须在 agent-service 之前
systemctl enable --now fettle-standalone-user-service
systemctl enable --now fettle-standalone-ai-grpc
systemctl enable --now fettle-standalone-ai-engine
systemctl enable --now fettle-standalone-agent-service
systemctl enable --now fettle-standalone-chat-service
systemctl enable --now fettle-standalone-skill-service
systemctl enable --now fettle-standalone-billing-service
systemctl enable --now fettle-standalone-gateway
```

#### 7A.3 常用命令

```bash
# 查看所有服务状态
systemctl status fettle-standalone-*

# 重启某个服务
systemctl restart fettle-standalone-gateway

# 查看实时日志
journalctl -u fettle-standalone-chat-service -f

# 停止全部
systemctl stop fettle-standalone-{gateway,user-service,agent-service,chat-service,skill-service,billing-service,ai-engine,ai-grpc}
```

#### 7A.4 注意事项

- `.env` 路径在 `backend/shared/config/config.go` 中硬编码为 `/www/wwwroot/fettle-standalone/.env`，服务启动时自动加载，无需额外配置环境变量。
- **agent-service 启动时会阻塞连接 ai-engine gRPC（端口 20008）**，如果 gRPC 未启动，agent-service 会卡住不监听 20003 端口。务必先启动 `fettle-standalone-ai-grpc`。
- 更新二进制后需重启对应服务：先 `systemctl stop`，再替换文件，再 `systemctl start`（直接覆盖运行中的二进制会报 "Text file busy"）。

---

### 方案 B：使用宝塔 Go 项目管理器

适合习惯在宝塔面板 GUI 中管理进程的场景。

#### 7B.1 添加 Go 项目

在宝塔面板 → 网站 → Go项目 → 添加项目，逐个添加：

| 项目名称 | 可执行文件路径 | 端口 | 备注 |
|---|---|---|---|
| standalone-gateway | `/www/wwwroot/fettle-standalone/build/gateway` | 20001 | 网关 |
| standalone-user | `/www/wwwroot/fettle-standalone/build/user-service` | 20002 | 用户认证 |
| standalone-agent | `/www/wwwroot/fettle-standalone/build/agent-service` | 20003 | 智能体 |
| standalone-chat | `/www/wwwroot/fettle-standalone/build/chat-service` | 20004 | 对话 |
| standalone-skill | `/www/wwwroot/fettle-standalone/build/skill-service` | 20005 | 技能 |
| standalone-billing | `/www/wwwroot/fettle-standalone/build/billing-service` | 20006 | 计费 |

> 建议项目名称加 `standalone-` 前缀，避免与多租户版 Fettle 的服务混淆。

#### 7B.2 环境变量配置

在宝塔项目配置中使用"从文件加载"，文件路径：

```text
/www/wwwroot/fettle-standalone/.env
```

如果你的宝塔面板不能加载 `.env`，请改为手动指定以下环境变量：

- `APP_PORT` 对应服务端口
- `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`
- `REDIS_ADDR`
- `JWT_SECRET`
- `AI_ENGINE_GRPC_ADDR`（agent-service 需要）
- `MONGO_URI`, `NATS_URL`（chat-service 需要）
- `MINIO_ENDPOINT`（skill-service、agent-service 需要）

#### 7B.3 Python 项目：ai-engine

在宝塔面板 → 网站 → Python项目 → 添加项目：

| 配置项 | 值 |
|---|---|
| 项目名称 | standalone-ai-engine |
| 框架 | FastAPI |
| 项目路径 | `/www/wwwroot/fettle-standalone/backend/ai-engine` |
| 启动命令 | `uvicorn main:app --host 0.0.0.0 --port 20007` |
| 端口 | 20007 |
| Python 环境 | 选择项目下的 venv |

gRPC 服务（端口 20008）宝塔 Python 项目管理器不方便管理，建议仍用 systemd：

```bash
systemctl enable --now fettle-standalone-ai-grpc
```

或者用宝塔"计划任务"添加一个开机启动脚本。

#### 7B.4 注意事项

- **不要同时用 systemd 和宝塔管理同一个服务**，会导致端口冲突。如果之前已创建了 systemd 服务，先 `systemctl disable --now fettle-standalone-*` 全部停掉再在宝塔里添加。
- 宝塔 Go 项目管理器没有启动顺序控制，agent-service 可能在 ai-grpc 之前启动。如果 agent-service 启动后 20003 端口没监听，手动重启一次即可。
- 更新二进制：在宝塔面板中先停止项目 → 替换文件 → 再启动。

### 7C. 前端网站配置（两种方案通用）

在宝塔面板 → 网站 → 添加站点：

| 网站名称 | 站点目录 | 备注 |
|---|---|---|
| standalone.fettle.cenkor.cn | `/www/wwwroot/fettle-standalone/frontend/web-admin/dist` | 管理后台 |

Nginx 配置要点（在站点配置中添加）：

```nginx
# 前端 SPA 路由
location / {
    try_files $uri $uri/ /index.html;
}

# API 反向代理到 gateway
location /api/ {
    proxy_pass http://127.0.0.1:20001/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;
}

# WebSocket 支持
location /ws/ {
    proxy_pass http://127.0.0.1:20001/ws/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;
}
```

> 注意：宝塔建站后会自动生成 nginx 配置，需要手动把上面的 `location` 块加进去，替换掉默认的 `location /` 配置。

SSL 证书：在宝塔面板 → 网站 → 站点设置 → SSL → 一键申请 Let's Encrypt。

## 10. 启动顺序与健康检查

### 10.1 启动顺序

1. PostgreSQL / Redis / MongoDB
2. MinIO / NATS / Milvus
3. AI Engine gRPC（端口 20008）← **必须在 agent-service 之前**
4. Go 后端服务（user → agent → chat → skill → billing → gateway）
5. AI Engine HTTP（端口 20007）
6. 前端网站（Nginx 静态托管）

### 10.2 验证访问

- 管理后台：`http://standalone.fettle.cenkor.cn`（或 `http://主机IP` 直接访问）
- API 网关健康检查：`curl http://127.0.0.1:20001/health`
- AI 引擎健康检查：`curl http://127.0.0.1:20007/health`

### 10.3 端口清单

| 服务 | 端口 | 说明 |
|------|------|------|
| Gateway | 20001 | API 网关 |
| User Service | 20002 | 用户与认证 |
| Agent Service | 20003 | 智能体管理 |
| Chat Service | 20004 | 对话服务 |
| Skill Service | 20005 | 技能市场 |
| Billing Service | 20006 | 计费统计 |
| AI Engine HTTP | 20007 | AI 引擎 HTTP 接口 |
| AI Engine gRPC | 20008 | AI 引擎 gRPC 接口 |

### 10.4 常见问题

- `JWT_SECRET` 未配置：服务启动失败
- 数据库连接失败：检查 `.env` 中数据库地址/密码
- 端口冲突：检查是否有其他服务（如多租户版 Fettle）占用相同端口
- agent-service 启动后 20003 不监听：ai-grpc 未启动，先启动 gRPC 再重启 agent-service
- AI 引擎不可用：检查 `uvicorn` 启动日志（`journalctl -u fettle-standalone-ai-engine -f`）
- 前端显示"站点创建成功"默认页：检查 nginx 配置的 root 是否指向 dist 目录，以及是否通过 HTTPS 访问但未配置 SSL
